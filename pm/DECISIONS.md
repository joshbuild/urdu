2026-09-18 (260918c): The SRS design in `research/urdu-vocabulary-srs-research-and-design.md` is accepted as the new direction (sponsor, with ChatGPT research). It keeps one shared schedule per item and changes the following:
- Recognition deltas become −2/−1/0/0/+1. This supersedes the recognition half of 260918b; production stays −1/0/0/+1/+2.
- The fixed 0/1/5/25/125/625/3125-day ladder is replaced by an immutable, versioned geometric ladder from 3 hours to about 10 years, with five quarter-step presets (2^1 to 2^2) and Moderate 2^1.25 as the default. Scheduling uses exact durations and due timestamps, not dates.
- Review events record the applied delta, the ladder version, before/after interval and due, and prompt support.
- A ladder change is non-retroactive: an item on an old ladder moves to the active one at its next review, mapped to the logarithmically nearest rung.
- Legacy items migrate onto a legacy ladder version with their due times unchanged.
- Direction statistics choose the prompt direction and never schedule.

Rationale: two-rung moves on a ×5 ladder made ×25 scheduling commitments, and no fixed multiplier is universal, so the choice should be explicit and switchable. Rejected: separate per-direction schedules and an FSRS-style adaptive model, both deferred until real history shows the fixed ladder's limits. The report's §11 items stay open. This is a cross-cutting refactor touching the schema, `shared/`, the Worker, the PWA, the PRD, VISION §6 and the AGENTS invariants, to be planned as its own work front. Ripples (at build): PRD FR-A/Appendix A, VISION §6, AGENTS invariants, `shared/mastery.ts`, `shared/dates.ts`.

Deferred: per-direction statistics and automatic direction choice; Coach speaking counts as production only for unprompted recall (f06). Ripples: VISION §6.3, PRD FR-A4, AGENTS invariants.

2026-09-17 (260917g): Regexes over non-ASCII or invisible characters are written as explicit code-point data (commented ranges, or `String.fromCodePoint`), not as `\uXXXX` escapes inside a regex literal. Biome's formatter decodes those escapes into literal characters when it rewrites a file, and f03's tokenizer came back with a no-break space sitting invisibly in its source. A character class nobody can see cannot be reviewed, and a later edit can delete a character without anyone noticing. Rejected: suppressing the formatter per line (hides the rule rather than following it); keeping the literals with an explanatory comment (the invisible bytes outlive the comment).
2026-09-17 (260917c): The FR-B4 build secret scan (`scripts/scan-bundle.mjs`) applies a different rule per build directory. `dist/client` — the assets Cloudflare serves to the browser — fails on a secret *name* as well as a *value*: a name in client JS means the frontend is reaching for a binding it must never see. `dist/urdu`, the Worker bundle, fails on values only, because the Worker legitimately references `c.env.UNLOCK_SECRET` and a names rule there is a false positive on every build. `dist/urdu/.dev.vars` is exempt: the Vite plugin copies it beside the bundle for `wrangler dev` and it is not uploaded (the 2026-09-17 deploy uploaded only the `dist/client` assets). Rejected: allow-listing the literal `UNLOCK_SECRET` string in the Worker bundle, which would have suppressed the name rule without saying why, and scanning `dist/client` alone, which was the pre-existing gap. The value rule was confirmed to fire by appending the dev secret to the built bundle and re-running the scan. Ripples: AGENTS.md commands (`pnpm check`'s last step now covers both directories).
2026-09-17 (260917b): The Windows execution failures that blocked this front for three sessions — `spawnSync ... biome.exe EPERM`, `spawn EPERM` from Miniflare, and `[vitest-pool]: Timeout starting cloudflare-pool runner` — are attributed to AVG Antivirus, which is the machine's active scanner and has disabled Defender (`Get-MpComputerStatus` returns `0x800106ba`; `root\SecurityCenter2` lists AVG). Evidence: a plain directory rename inside the repo took over 120 seconds, and worker-pool runs degraded from green to 2-of-5 files never starting a runner within one session, with no code change between. `@biomejs/biome` stays pinned at 2.5.10 — `pnpm dlx @biomejs/biome@2.5.13 --version` reproduces EPERM from a fresh cache path while 2.5.10 runs, which reads as AVG blocking a binary it has not seen rather than a Biome defect. The same undocumented change also moved `@cloudflare/vite-plugin` to 1.54.4 and wrangler to 4.129.0; retained untested, since the set passes. Rejected as causes after testing: stale miniflare SQLite `-shm`/`-wal` files from a force-killed dev server (moving `.wrangler` aside changed nothing), and the `maxWorkers: 2` cap (the green 194-test run was already under it). Confirmed the same session by toggling AVG: Hardened Mode off removes the runner timeouts outright (3/5 → 5/5 worker files, 217 s → 88 s) and CyberCapture off halves the rest (→ 48 s, 38 s warm), leaving ≈ 7 s of File Shield scanning per `workerd` launch. Exclusions were then tested and rejected on evidence: a repository folder exception, with both features still off, took the same suite to 492 s and back to 3 of 5 files — eight times worse than no exception — apparently because editing settings on this console-managed install (AVG Business Security 26.8) provokes a policy re-sync that discards the local toggles. Removing it and re-toggling both features off gave 8 s for the worker project and 32.7 s for a full `pnpm check`, better than any earlier measurement. Standing arrangement: **no AVG exceptions**; toggle Hardened Mode and CyberCapture off for a work session and back on after. Ripples: f01 s07's verification gate; any future run of this shape is environmental and re-run before being read as a code defect.
2026-09-17 (260917b): Vitest is capped at `maxWorkers: 2` in `vitest.config.ts`, and agents run it one at a time.
